## Local arm64-only release build (this Linux box)
No Node/JDK on PATH by default. Toolchain installed under `/tmp/opencode/`:
- JDK 17 Temurin: `/tmp/opencode/jdk17` (JAVA_HOME)
- Node 22: `/tmp/opencode/node22` (for the RN JS bundle step)
- `ANDROID_HOME=/home/userver/android-sdk`
- Build command:
  ```
  cd android && ANDROID_HOME=/home/userver/android-sdk JAVA_HOME=/tmp/opencode/jdk17 \
  SENTRY_DISABLE_AUTO_UPLOAD=true \
  PATH="/tmp/opencode/jdk17/bin:/tmp/opencode/node22/bin:$PATH" \
  ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a --console=plain
  ```
- `-PreactNativeArchitectures=arm64-v8a` overrides `reactNativeArchitectures` in `android/gradle.properties` (all ABIs) → APK contains ONLY `arm64-v8a` (verified via `aapt2 dump badging` → `native-code: 'arm64-v8a'`).
- `SENTRY_DISABLE_AUTO_UPLOAD=true` required, else `createBundleReleaseJsAndAssets_SentryUpload_*` fails (no `SENTRY_AUTH_TOKEN` here).
- Output: `android/app/build/outputs/apk/release/app-release.apk` (~38 MB).
- Typecheck: `PATH="/tmp/opencode/node22/bin:$PATH" node node_modules/typescript/bin/tsc --noEmit`.

## The markdown scaling bug — ROOT CAUSE (bold/italic/strikethrough ignored font size)
- react-native-marked computes emphasis styles as `StyleSheet.flatten([fontStyle.regular /* fontSize:16, lineHeight:24, hardcoded */, modifier, userStyles.strong])`. If the theme does NOT provide `strong`/`em`/`strikethrough` (and `link`, `li`, `h4-h6`) keys, the lib's hardcoded 16px wins and the Parser injects it into the `styles` arg, defeating any renderer-level merge.
- **Fix**: `Markdown.tsx` theme now gives EVERY font-carrying key the scaled base text style: `text`, `strong/em/strikethrough` (base + modifier), `link`, `li`, `h4/h5/h6`. `base = {color, fontSize: scaled(BASE_SIZE,f), lineHeight: scaled(22,f)}` in `lightTheme(acc, f)`; dark theme overrides colors (`strong/em/strikethrough/li` → `#e5e5e5`, `link` → `acc.dark.soft`, h4-h6 → `#ffffff`). Removed the old renderer `baseText`-merge workaround (constructor no-arg now).
- Earlier attempts (renderer-level `baseText` merge) FAILED for the same reason — parser-injected hardcoded style overrode the merge. Verified with a standalone `react-test-renderer` harness (`/tmp/opencode/rendertest`, mock react-native, REAL react-native-marked commonjs): bold stayed `fontSize:16` pre-fix at 50%; after fix, everything scales 8/15/30 at 50/100/200% (h3 base 16). Harness notes: react-test-renderer 19 needs `TestRenderer.act()` around `create` (concurrent mode) else tree is empty.
- Debug build pipeline details live in `AGENTS.md`/this file: `-PreactNativeArchitectures=arm64-v8a` makes the arm64-only APK; `SENTRY_DISABLE_AUTO_UPLOAD=true` avoids the Sentry token failure. `ndk { abiFilters }` and `splits { abi }` blocks in build.gradle do NOT apply to RN/expo prebuilt jniLibs — only `-PreactNativeArchitectures` works (build.gradle is reverted after using it; kept universal for CI).
